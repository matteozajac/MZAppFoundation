# Codex for Open Source application notes

Verified against official sources on 2026-10-21. These notes prepare an application;
no application has been submitted and no benefit has been awarded.

## Program and prerequisites

[Codex for Open Source](https://developers.openai.com/community/codex-for-oss)
offers selected maintainers six months of ChatGPT Pro with Codex. Additional API
credits and Codex Security access have their own review. Selection considers
usage, ecosystem importance, and active maintenance; publication alone does not
establish eligibility or guarantee acceptance.

The [application form](https://openai.com/form/codex-for-oss/) asks for a public
GitHub profile and repository, the email associated with the ChatGPT account,
maintainer role, and a qualification explanation of up to 500 characters. Supply
account details directly in the form, not in repository files. Complete optional
API-credit details only if requesting that benefit.

Read the [program terms](https://learn.chatgpt.com/docs/codex-for-oss-terms) when
applying. Benefits and availability can change; applications are reviewed on a
rolling basis. Do not submit confidential information.

- Maintainer: Mateusz Zając (`matteozajac`); primary maintainer.
- Project: Swift infrastructure for injectable telemetry and purchases, provider

- Maintenance evidence: versioned releases and source history, automated core and
  tooling tests, integration documentation, and privacy-focused reporting fixes.
- License: MIT for original project files; dependencies retain their own licenses.

At preparation time the repository was private, with zero stars and zero forks.
Those figures do not measure private adoption. Do not claim public downloads,
community adoption, production integrations, or device validation without evidence.
Collect current metrics and any permissioned public integration examples after
publication. Keep private app names and user reports out of the application.

## Suggested qualification answer

This draft is under 500 characters and focuses on demonstrable function:

> I created and maintain MZAppFoundation, a Swift package for reusable Apple-app infrastructure: injectable telemetry and purchases, isolated provider adapters, structured error diagnostics, developer settings, and privacy-conscious bug reports. It includes versioned releases, automated tests, sample apps, and integration tooling. I am opening it to help Apple developers reuse and maintain this infrastructure.

## Suggested maintenance-use answer

Use this only where the form asks how tools or API credits would be used; it is a
future plan, not a claim of an existing API-backed service:

> I would use Codex to review changes, reproduce bug reports with synthetic fixtures, maintain Swift concurrency and platform compatibility, test provider adapters, and update integration docs. If API credits are granted, I would use them for maintainer-reviewed issue triage and pull-request review, with scoped permissions and no private reports or credentials sent automatically.

## Before applying

1. Complete the [publication checklist](open-source-release.md) and verify public
   access to the repository, license, README, and contributor guidance.
2. Link passing public CI runs and releases that contain the open-source license.
3. Describe actual maintenance responsibilities and current usage honestly. A new
   public project may need time to establish useful adoption evidence.
4. Review and submit the form personally using the correct ChatGPT account.
